Shapes first: the numpy moves behind a transformer, and nine ways to break them

Every part of a transformer is a few lines of array code, and almost every mistake in those lines is a mistake about shape: how many rows, how many columns, and which axis is which. This page shows the three moves that matter most, on small examples made for it. Then a real comparison of a vision transformer and a convolutional network after 3 passes and after 30. It ends with nine real typing mistakes from one afternoon. One of them gives no error at all.

Three habits for array code

Print the shape after every stepOne line, print(x.shape), after each move. A wrong shape caught on the line that made it takes seconds to fix. The same wrong shape caught five steps later arrives as an error about a layer you never wrote.
A correct shape is not a correct resultThe first panel has two versions with identical shapes, and one of them is scrambled. For anything that cuts or rearranges, do the reverse and compare with what you started with, or draw one example and look at it.
When you copy a cell, change the data names firstA leftover name from the cell above still exists, so Python cannot warn you. It will train the new model on the old model's data, or check it against the wrong pictures.
