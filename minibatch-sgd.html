Minibatch size: noise against speed

One example per update is noisy. All 1,500 per update is exact but slow to get going. A minibatch sits in between: averaging b examples cuts the noise by about √b, and the computer can process them together. Move the slider, then run the race.

The last column is the timing the book measured on its airfoil dataset (1,500 examples) in Section 12.5 of Dive into Deep Learning: 0.020 seconds per epoch for full gradient descent, 0.685 for batch size 1, 0.090 for batch size 10 and 0.025 for batch size 100. All four reached about the same loss (0.245 to 0.247). Batch size 1 learns the most per example but takes 34 times longer per pass, because the computer handles 1,500 tiny updates one at a time instead of using vectorized arithmetic. A batch of 100 is nearly as fast per pass as the full batch and makes 15 updates in that time.

This page uses its own small dataset (1,500 examples, two weights, so the path can be drawn) with the book's batch sizes and learning rates: 1 for the full batch, 0.4 for b = 100, 0.05 for b = 10 and 0.005 for b = 1. The predicted spread is σ / √b, with a correction for drawing from a finite dataset, which is why the noise falls to zero when b reaches all 1,500 examples.
